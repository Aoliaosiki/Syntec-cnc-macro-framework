# Syntec CNC 宏程序维护框架

![Release](https://img.shields.io/badge/release-2026.11.25-blue)
![Agent](https://img.shields.io/badge/agent-Codex%20%7C%20Claude%20%7C%20CodeBuddy-lightgrey)
![Focus](https://img.shields.io/badge/focus-CNC%20macro-orange)
![License](https://img.shields.io/badge/license-custom-red)

一套给 AI Agent 用的**新代（Syntec）CNC 宏程序维护方法框架**：把「拿到一个备份或交付包 → 认出每个宏是干什么的 → 判断改一处要同步哪些文件 → 改完自检 → 交付」这件事，固化成可复用的流程、指纹表和检查清单。

它不是宏程序库，也不是参数手册。它提供的是**判断方法**：怎么认功能、怎么规划变量、怎么换算单位、怎么防止漏改。

- 不按文件名/宏号猜功能，按内容指纹识别对刀、对落差、断刀、盘刀、换刀、攻牙、MST。
- 改一处先列同步矩阵，避免只改主宏、漏掉孪生入口与三语报警。
- 变量按 `#` / `@` / `R` 三个地址空间规划，不背固定地址。
- 单位换算先判 `Pr17`、`Pr3241`、`G70/G71` 与值来源，避免公制/英制混算。
- 支持接入使用者自有的 Wiki/MCP 做 L2 规格校验，失败可降级为 L1。

> 本仓库是**框架版**：只含通用方法与公开语法，不含任何厂商内部页面、客户项目、具体参数/报警号表、现场案例或内部版本信息。
> 需要具体机型规格时，请接你自己的知识库；结论必须标注能力级别。

## 它解决什么问题

| 现场问题 | 常见错误做法 | 本框架的做法 |
|---|---|---|
| 宏文件名被客户改过 | 看文件名/宏号下结论 | 读文件头 + 关键 token + 数据流，按内容指纹判功能 |
| 同功能有 G/M/O 多个入口 | 只改正在调试的那一个 | 按内容 diff 找孪生，主宏与所有入口同改 |
| 参数/报警/画面跨文件 | 改完宏就算完成 | 按同步矩阵逐项核对参数表、三语、画面、PLC |
| 公制/英制换算错 | 长度和速度都除 25.4 | 先判 `Pr17` / `Pr3241` / `G70/G71`，长度 `/2.54`、速度 `/25.4` |
| 变量地址互相踩 | 随手拿一个没用的 `#`/`@` | 先画数据流，按生命周期选空间，查 PLC/画面/其它宏占用 |
| 规格与现场不一致 | 凭记忆或“通常是这样” | 有 L2 证据才写结论，否则标“草案/未校验” |

## 覆盖的宏类型

按**内容**识别，不按文件名。下表是判功能的起点，不是固定映射。

| 功能 | 强特征 | 常见误判 |
|---|---|---|
| 对刀 | `G31` + 刀长表写回 + 刀号引数 + 磨耗清零 | 只看到 `G31` 就认定对刀 |
| 对落差 | `G31 Z` + 工件坐标系写回 + 落差变量 | 与对刀同为 `G31`，区别在写回目标 |
| 断刀 | `G31` + 公差 + 刀号相关报警 + 刀长比对 | 不同包可能有多个入口名，按内容判 |
| 盘刀 | `M19`/定向 + 多刃循环 + 角度参数 | 把普通铣削循环当盘刀 |
| 换刀 | `T`/`M6` + 刀库状态 + 主轴定向 + 握手寄存器 | 认为下 `T` 就一定换刀 |
| 攻牙 | `G84`/`G84.48` + 主轴/进给/回退 | 忽略每转进给与公/英制差异 |
| MST | 画面寄存器 + M/S/T 下发 + 模式限制 | 只看画面，不看 PLC 握手 |

补充两条现场口径：

- **钻攻与加工中心换刀不同**：钻攻常见固定入口 `T0000`；加工中心多数必须下 `M6` 才真正换刀，`T` 码只负责转刀盘。是否自动补 `M6` 由参数/PLC 决定，必须按包确认。
- **对刀与对落差都围绕 `G31`**：判定关键是“写回哪里”——写刀长表是对刀，写工件坐标系是对落差。

## 安全边界

- **不猜地址**：参数号、报警号、`@`/`R` 映射必须有来源（包内文件、参数表、PLC 工程或 L2 页面）。
- **不建立固定 G/M 对应**：同一个 G 号在不同包里可能是不同功能；同功能也可能有多个入口名。
- **不整目录转码**：宏常见 GBK、首行 `%@MACRO`；XML 常见 UTF-8 + BOM；逐文件保持原编码与换行。
- **不整文件重写**：优先精确替换，`old` 字符串必须唯一命中。
- **不替代官方手册**：地址范围、参数定义、报警号段以实际控制器与本包文件为准。
- **不直接操作设备**：本框架只处理文件与方法，不联网上传 CNC、不改控制器。
- **不发布第三方资料**：厂商手册、客户数据、内部页面与参数/报警号表不随本仓库分发。

## 能力分级 L1 / L2 / L3

不要把“登录成功”当能力，用可验证的返回判定。

| 级别 | 解锁条件 | 允许做什么 | 不允许做什么 |
|---|---|---|---|
| L1 本地基线 | 能读本地文件 | 盘点、编码/换行检查、diff、语法结构分析、草案 | 不得宣称“符合最新规格/可交付” |
| L2 规格校验 | 自有 Wiki/MCP 的搜索与读页实际返回成功 | 核对参数语义、报警号、动作流程、机型差异 | 未校验项不得写成确定结论 |
| L3 交付 | L2 通过 + 本地自检通过 | 出交付包、导入顺序、首设参数、验证项 | 未过 L2 的规格敏感改动不得交付 |

**降级规则**：无 MCP、无权限、网络失败、页面不存在时，继续完成本地工作，但结论与交付物必须标注 `云端校验：未完成`，并列出待查页面/字段。不得用“应该/大概/通常”补空。

每次任务开头建议标注：

```text
能力级别：L1 / L2 / L3
云端校验：通过 / 未完成 / 不适用
```

## 快速开始

### 1. 只做盘点，先不改

```text
用 syntec-cnc-macro-framework 盘点这个备份：<path>
只做 L1：目录结构、宏清单、编码/换行、入口形态、可疑孪生。
不要修改任何文件，输出盘点表和缺口清单。
```

### 2. 让 Agent 先认功能

```text
按 references/macro-core.md 第一部分的指纹，给 Macro/ 下每个文件打功能标签。
标注判断依据（关键 token、写回目标、引数）和置信度，不要用文件名直接下结论。
```

### 3. 改之前先出台账

```text
按 references/change-playbook.md 的同步矩阵，列出这次改动的台账：
要改的文件、参数、报警三语、画面、PLC、文档，以及孪生关系。
涉及具体参数号/报警号的地方标“待 L2 校验”，不要猜。
```

### 4. 改完自检

```text
按 change-playbook 第二部分跑自检：孪生 diff、报警号定义、参数上下限、
编码/换行、单位换算分支。输出逐项结果，失败项直接列出来。
```

### 5. 交付

```text
输出交付说明：导入顺序、首设参数、验证项、报警触发方法、
本次云端校验记录。未过 L2 的改动标“草案”。
```

## 标准工作流

### 第 0 步：判目录与机型

- `*_MB_*` / `*_MBL_*` 且含 `Macro/`、`Parameter/`、`ParameterExt/`、`Ladder/`、`OCRes/`、`AlarmMacro/` → 控制器全备份。
- 平铺（`Macro/` + `paramext.pxt` + 报警 XML + `cnc.lad` + 客制包）→ 交付包。
- 同一客户可能有多套机型，参数号段、报警号段、换刀入口、画面口径会分叉，不能互抄。
- 先查本地资料，再决定是否要 L2 回查原页。

### 第 1 步：盘点

盘点文件清单、宏数量、参数表、报警文件、客制画面、PLC、机台信息；按**内容指纹**给每个宏打角色标签。

### 第 2 步：建台账

列出「要改的文件 / 参数 / 报警 / 画面 / PLC / 文档」，标注编码、换行、孪生关系、三语关系。先呈现计划再动手。

### 第 3 步：修改

- 复制整套到工作目录再改，不要只改单文件。
- 精确替换：`old` 字符串唯一命中；保留编码/换行/BOM。
- 先改主宏，再同步所有同功能孪生；参数/报警三语同改。

### 第 4 步：自检

- G/M/O 孪生非注释差异 = 0；
- 宏内报警号全部有定义，无占位、无同号异义；
- 参数上下限与宏校验一致，默认值不预置现场值；
- 关键 token 在位（`G31`、刀长表、`M19`、报警表达式等）；
- 编码/换行未变。

### 第 5 步：交付

写导入顺序（先客制包 → 再覆盖报警/参数/宏 → 最后画面/PLC）、首设参数、验证项、报警触发法、云端校验记录；未过 L2 明确写“草案”。

## 关键方法摘录

### 一、先认功能，再谈改法

识别顺序固定为：读文件头注释 → 看入口形态 → 看关键 token → 看数据流 → 找孪生。文件名、宏号、注释都可能是错的，**代码分支才是事实**。

### 二、变量先分三个空间

| 空间 | 常见范围 | 型态 | 生命周期 |
|---|---|---|---|
| 区域变数 `#` | `#1~#400` | Double | 本次宏/子程序执行期间 |
| 轴群记忆 `#` | `#401~#999` | Double | 断电保持（按轴群） |
| 系统变数 `#` | `#1000` 以上 | Long/Double | 随系统状态 |
| 公用变数 `@` | `@1~@165535` | Double/Long | 由区段与参数决定 |
| PLC 寄存器 `R` | `R0~R65535` | 32 位整数 | 由控制器/电池决定 |

关键约束：

- `#1~#26` 是 A~Z 引数专用，`#27~#400` 才是自由局部区；`#33` 不是“第 33 个引数”。
- `R` 只能存整数，传小数要放大（如 ×1000）后写，读侧再除。
- 写 `R` 后、读同一 `R` 前必须 `WAIT()`。

常见 `@` 与 `R` 映射：

```text
@ = 100000 + R     // R0~R65535，建议统一用这一段
@ = 10000  + R     // R0~R4095，旧别名，与上一段同区
@ = 400    + R     // R1~R255
```

### 三、扩充参数的读取路径不止一条

以常见 `Pr50xx` 段为例，同一个参数可能同时有参数号、`R` 镜像、`#` 只读值和 `@` 映射：

```text
R  = 8000 + (Pr - 5000)
Pr = 5000 + (R - 8000)
#  = Pr
@  = 100000 + R
```

但这不是全局公式：`Pr34xx` 等其它段、不同机型、不同版本都可能不一样。**必须按包内 `paramext.pxt`、`ParamExt_*.xml` 与 PLC 定义确认**，不能拿一条公式套所有参数。

### 四、单位换算先判四个开关

| 开关 | 作用 | 注意 |
|---|---|---|
| `#1010` | 当前 `G70` / `G71` | 切换后必须恢复，报警退出也要恢复 |
| `Pr17` | LIU 分辨率 | 公制 0.01/0.001/0.0001 mm；英寸 0.001/0.0001/0.00001 in |
| `Pr3241` | 小数点型态 | `=0` 与 `=1` 两支都要测；`=1 + G70` 可能二次缩放 |
| 值来源 | 参数镜像/当前值/画面值 | 参数镜像 `@108xxx` 固定 0.001mm，不等于当前 LIU |

常用换算：

```text
英寸长度  ->  /2.54      // 不是 /25.4
英寸速度  ->  /25.4
0.001°    ->  /1000.
攻牙每转  ->  G70: 1.0/#8    G71: 25.4/#8
```

### 五、改一处，先想清楚要同步几处

| 改动点 | 必须同步 |
|---|---|
| 宏入口/引数 | 主宏 + 所有同功能 M/O 孪生 + 调用方程序 + 交付说明 |
| 变量/寄存器 | 主宏 + 孪生 + PLC + 画面 + 变量台账 + 交付说明 |
| 参数 | 参数表 + 三语 XML + 宏读取点 + PLC 引用 + 画面 |
| 报警 | 报警 XML/CSV + 三语 + 所有调用点 |
| 画面 | `MST.xml`/`Backgnd.xml` + 寄存器 + 宏 + PLC |
| PLC | 源工程 + 编译产物 + 宏握手 + 文档 |
| 安装包 | 覆盖顺序 + 旧文件回退检查 |

顺序反了，安装包里的旧文件会把新改动覆盖回去。

## 常见坑

1. **按文件名/宏号认功能**：宏号可被任意修改，必须看内容。
2. **只改 G 码主宏**：同功能 M/O 入口没同步，现场走另一入口就复现旧问题。
3. **只改简中报警**：繁中/英文仍是占位，切换语言就露馅。
4. **改了参数号没改三语和画面**：参数表对、界面仍是旧文案。
5. **改了宏读取的寄存器没改 PLC**：宏永远读到默认值。
6. **变量地址未查占用**：与 PLC、画面、其它宏冲突，表现为偶发。
7. **把参数镜像当当前 LIU**：`@108xxx` 固定 0.001mm，`G70` 下直接混算必错。
8. **长度和速度用同一个系数**：长度 `/2.54`，速度 `/25.4`。
9. **只测 `Pr3241=0`**：`=1` 以及 `=1 + G70` 的叠加分支没测。
10. **`G70/G71` 切了不恢复**：正常退出恢复、报警/中断退出没恢复，污染后续程序。
11. **整数除法截断**：需要小数时写 `/1000.`，不是 `/1000`。
12. **整目录转 CRLF 或整文件重写**：编码、BOM、换行全被破坏，diff 无法审。

## 常见问题

**Q：能不能直接告诉我某个 G 码/宏号怎么改？**

不建议。宏号可被改名，同一个 G 号在不同包里可能是不同功能。请提供文件内容或备份，让 Agent 按内容指纹判断；跨包“同名同义”的假设最容易出错。

**Q：没有 Confluence / Wiki 能用吗？**

能，但只能到 L1：可以完成盘点、语法分析、编码检查、变量与单位核对、改动草案。涉及参数语义、报警号段、机型差异的结论必须标“待校验”。

**Q：支持哪些控制器和版本？**

框架面向新代（Syntec）宏体系，重点是通用语法与方法。具体地址范围、参数定义、报警号段随控制器与版本变化，必须按实际备份和官方手册确认。

**Q：会不会把我的文件改坏？**

框架要求先备份、复制整套再改、精确替换、保留编码/换行/BOM，并在交付前做孪生 diff 与编码检查。但最终写入由执行方完成，仍建议在副本上操作并保留原包。

**Q：能不能批量处理整个目录？**

可以盘点整个目录，但不建议批量改写。宏文件编码与换行常不一致，批量替换会破坏未被注意的文件；应逐个确认后精确修改。

**Q：和 PLC / 梯图 skill 是什么关系？**

宏负责 G/M/T 入口、参数读写、报警触发与握手；PLC 负责寄存器、互锁与执行。改宏涉及的 `R`/`@` 地址、握手时序、报警位，必须与 PLC 侧一起核对。

**Q：为什么公开版没有具体参数表和报警号表？**

那些内容属于厂商/客户资料，随版本和项目变化，也不适合公开分发。公开版保留“怎么查、怎么判、怎么同步”的方法，具体表由使用者自己的知识库提供。
