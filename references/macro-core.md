# 宏核心：功能识别、语法、变量与单位

> 按“先认功能，再查语法，再规划变量，最后算单位”的顺序阅读。

- 第一部分：功能识别
- 第二部分：宏语法与调用
- 第三部分：变量与寄存器
- 第四部分：单位、精度与公英制

# 第一部分 功能识别

> 宏文件名可以被客户或项目任意修改，**不要用文件名/宏号做唯一判断**。先读文件头注释，再看关键 token 与数据流。

## 一、识别顺序

1. **读头部注释**：用途、引数、依赖参数、报警号、版本。
2. **看入口形态**：G 码宏、M 码宏、T 码宏、`G65` 子程序，决定它怎么被调用。
3. **看关键 token**：`G31`、刀长表读写、`M19`、坐标系写入、报警表达式。
4. **看数据流**：读哪些参数/寄存器，写哪些变量/刀表/坐标系，最后返回什么。
5. **找孪生**：同目录/同包里内容相近的 G/M/O 文件，按 diff 确认，不预设固定映射。

## 二、功能指纹

| 功能 | 强特征 | 弱特征 |
|---|---|---|
| 对刀 | `G31` + 刀长表写回 + 刀号引数 + 磨耗清零 | 页面参数、吹气 M 码 |
| 对落差 | `G31 Z` + 工件坐标系写回 + 落差变量 | 坐标系号引数 |
| 断刀 | `G31` + 公差 + 刀号相关报警 + 刀长比对 | 快速/常规分支 |
| 盘刀 | `M19`/定向 + 多刃循环 + 角度参数 | 刀粒数、X/Y 偏置 |
| 换刀 | `T`/`M6` + 刀库状态 + 主轴定向 + 握手寄存器；钻攻常见 `T0000` | 刀臂/刀盘/刀库类型 |
| 攻牙 | `G84`/`G84.48` + 主轴/进给/回退 | 参数块、螺距校验 |
| MST | 画面寄存器 + M/S/T 下发 + 模式限制 | 自动清零、焦点寄存器 |

### 变量/寄存器指纹

| 写法 | 能说明什么 | 不能说明什么 |
|---|---|---|
| `#[11000+#61]` / `#[30000+...]` | 在读写刀表，`#61` 往往是刀号/索引 | 不能据此认定刀号一定存 `#61`，也不能认定轴型 |
| `@1080xx` / `R80xx` | 在读参数段的 PLC 镜像 | 不能认定参数语义；同号跨包可能不同义 |
| `#50xx` | 在读使用者参数值 | 不能当 R 镜像用；单位按参数定义 |
| `PARAM(n)` | 按参数号取配置 | 不能假定与 `@` 镜像同型态/同单位 |
| `@[#n]` / `#[表达式]` | 间接寻址，`#n` 是指针/偏移 | 不能认定 `#n` 的固定含义 |
| `M#n` | 间接 M 码 | 不能认定任意 M 号都能执行，必须已登记 |
| `#1036` | T 码数值（T 码宏常用） | 不是当前刀号寄存器 |
| `#1608` / `#1443` | G31 触发成功 / G31 触发坐标反馈 | 不能把 `#1443` 当任意时刻当前坐标 |
| `@502` | 某包约定的当前主轴刀号 | 不是所有包/版本固定用法 |

这些 token 只用来“认功能、找数据流”，不能用来背地址；写宏前仍要查变量空间、映射、占用与生命周期，见 `references/macro-core.md` 第三部分。

## 三、找同功能孪生

- 先按“功能 + 引数 + 写回目标”分组，而不是按文件名。
- 对候选文件做结构化 diff：忽略注释与空白，比较分支、报警号、参数读取、写回地址。
- 差异为 0 或仅注释差异 → 可视为同功能孪生。
- 差异在逻辑分支/报警/参数 → 说明是不同机型或不同版本，不能直接互抄。

## 四、常见误判

| 误判 | 纠正 |
|---|---|
| 文件名带某个 G 号就是某功能 | 宏号可被改；按内容判 |
| 两个文件都有 `G31` 就是同一功能 | 探针、对刀仪、断刀都用 `G31`，后续写回逻辑不同 |
| 报警号相同就是同一宏 | 可能是一号多义或不同机型号段 |
| 参数号相同就是同一语义 | 不同项目会重定义同一号段 |
| 注释写了功能就信注释 | 注释可能与代码不一致，以代码分支为准 |

## 五、记录模板

```text
文件：
功能：
入口：G/M/T/G65
引数：
读取参数/寄存器：
写回目标：
报警：
同功能孪生：
差异点：
置信度：高/中/低
```

# 第二部分 宏语法与调用

> 本文只讲通用写法，不含任何厂商内部参数号、报警号或客户数据。具体 G/M 代码、变量范围、报警编号以你所用控制器的官方手册为准。

## 一、文件形态

- 宏文件通常以 `%@MACRO` 开头，正文为可解析的宏语句。
- 常见编码为 GBK；部分控制器/工具链使用 UTF-8。**改动前先确认原文件编码与换行**，不要整目录统一。
- 同一目录里 CRLF 与 LF 可能并存；逐文件保持原样，避免整文件重写。
- 宏一般以 `M99` 结束；G 码宏、M 码宏、T 码宏的入口形式不同。

## 二、宏的分类与调用

| 类型 | 入口 | 说明 |
|---|---|---|
| G 码宏 | 由参数登记或固定 G 码调用 | 文件名与 G 号不必一一对应；同一行多个 G 码时只有最后一个能读引数 |
| M 码宏 | 由参数登记调用 | M 宏执行后常占用除 T 外大部分引数，同段后续 G 代码可能读不到 X/F |
| T 码宏 | 固定入口 `T0000`（钻攻换刀宏） | 是否读引数、是否再下 `M6` 由参数/PLC 决定 |
| `G65` | 非模态子程序呼叫 | `G65 P_ L_`；`P` 是程序号，`L` 是重复次数 |
| `G66`/`G66.1` | 模态呼叫 | 每个移动单节后执行，`G67` 取消 |

### 同一行多个功能码

- 同一行有多个 G 码宏时，通常只有**最后一个**能读到引数。
- G 与 M 同段：先解译 G；G 占用了轴向引数或 T 码，后面的 M/T 宏可能不执行。
- 同段多个 M 宏：多数控制器只执行第一个。
- 结论：功能宏尽量单独一行；不要把换刀、测量、轴移动挤在同一行。

## 三、变量与引数

> **不要背固定变量号。** `#`、`@`、`R` 是三个地址空间；某个号代表什么，由控制器规格、参数表、PLC 工程和本包宏的实际用法共同决定。完整方法与映射见 `references/macro-core.md` 第三部分。

| 写法 | 含义 | 注意 |
|---|---|---|
| `#1~#26` | A~Z 引数 | 引数专用，不要拿来做临时变量 |
| `#27~#400` | 局部变量 | 子程序与父程序共用，嵌套调用要防覆盖 |
| `#401~#999` | 轴群使用者记忆变数 | `#500~#999` 属于这一段 |
| `#0` | “未给” | 给 0 时变量值是 0，不等于 `#0` |
| `#100 ~ #199` | 常见公共变量区 | 不同控制器不同，不能当固定语义 |
| `#[表达式]` | 区域变数间接寻址 | 先算表达式再取该号变量 |
| `@n` / `R` 区 | 部分控制器用 `@` 映射 PLC 寄存器 | 换算规则以手册为准 |
| `PARAM(n)` | 按参数号取值 | 单位随参数定义 |

常见引数映射（以实际控制器为准）：

| 字母 | 常见变量 | 用途 |
|---|---|---|
| D | `#7` | 直径/刀补偏移 |
| H | `#11` | 刀长补偿号 |
| P | `#16` | 程序号/模式/参数 |
| Q | `#17` | 次数/公差/信号号 |
| R | `#18` | 半径/参考值 |
| T | `#20` | 刀号 |
| X/Y/Z | `#24/#25/#26` | 坐标 |

> 上表只是常用项；完整的 A~Z 映射（含 L=`#12`）见 `references/macro-core.md` 第三部分。G/N/O 没有对应 `#` 变量。

## 四、单位与类型（最大坑）

- PLC 寄存器/扩充参数常以 **0.001 mm 的整数**存储；参与坐标运算前要 `/1000.`。
- 同一参数的 `#` 只读镜像、`PARAM(n)` 与 `@`/R 镜像型态/单位可能不同，不能互当等价；先确认该参数定义。
- 先判单位口径：`#1010` 是 G70/G71，`Pr17` 决定 LIU（公制 0.01/0.001/0.0001mm；英寸 0.001/0.0001/0.00001in），`Pr3241` 决定小数点型态。
- 英寸侧长度/坐标 `/2.54`，速度/进给 `/25.4`；μm→mm `/1000.`；角度 0.001°→° `/1000.`。完整方法见 `references/macro-core.md` 第四部分。
- 整数除法会截断：`#7/2` 对 15 得 7；要 7.5 写 `#7/2.`。
- 一旦变量变浮点，地址值可能按 mm 解释，单位放大 1000 倍。
- 需要浮点结果时显式写小数点：`#65 := @108034 / 1000.;`（`@` 写法为示例，按实际寄存器替换）。

## 五、控制流

```gcode
IF cond THEN
    ...
ELSEIF cond THEN
    ...
ELSE
    ...
END_IF;

WHILE cond DO
    ...
END_WHILE;

FOR #27 := 1 TO 10 BY 1 DO
    ...
END_FOR;

CASE #83 OF
    1:
        ...
    2:
        ...
END_CASE;
```

- 漏分号时，部分控制器会把下一行合并解析；合并后语法合法就不报警，可能直接撞机。
- 报警后是否停机由系统设定决定；需要必停时显式 `M99` 或 `M00`。
- 写寄存器后、读同一寄存器前，必要时加 `WAIT()`/延时，避免预读旧值。

## 六、G31 跳步与探测

| 项 | 规则 |
|---|---|
| 指令 | `G31 Z... F...` / `G31 X...`；碰到跳脱信号立即停止当前移动 |
| 成功标志 | `#1608=1`；未触发时按包内逻辑报警 |
| 触发坐标 | `#1443` 为 **G31 触发时的 Z 机械坐标反馈**；只有刚执行过 Z 向 G31 才可这样用，不是任意时刻的当前 Z 坐标 |
| 速度 | `F` 是合成速度；页面设定速度与实际三轴合成速度可能不一致 |
| 跳脱信号 | 不写 `Q` 时通常用默认信号；改用其它 C-bit/驱动器信号时，必须在该段末尾加对应 `Q` |
| 共用性 | 探针、对刀仪、断刀检测都用 `G31`，但后续“写刀长/只比对/写落差”逻辑不同 |

**排查顺序**：确认必发并记录卡住行号 → 手给探头信号看输入点 → 单段执行 `G31` 验跳脱 → 看实际导通的信号位 → 在所有子程序的 `G31` 末补同一个 `Q`。

## 七、报警与提示

- `ALARM(n)`：只发编号，文字通常来自报警表/XML；三语（简中/繁中/英文）要同改。
- `ALARM(n,"文字")`：内嵌文字优先，但不利于三语维护。
- `MSG("...")`：只提示，不停机；需要停机用 `ALARM` 或 `M00`。
- 新增报警前先全包搜索该号，避免“一号多义”。
- 报警表里的占位文字必须替换，否则现场只看到“宏程序警报”。

## 八、调试与版本

- 保留文件头注释：用途、引数、依赖参数、报警号、版本/日期。
- 改参数/宏后同步更新版本日期（如参数表里的版本参数），否则现场无法判断新旧。
- 加密/编译宏解码即乱码，不要试图“修复乱码”或按文本改写。
- 同一功能的 G/M/O 文件内容必须一致（允许注释差异），改完做 diff。

# 第三部分 变量与寄存器

> 本文只讲通用方法与控制器常见映射，不含任何厂商内部页面、客户数据、项目参数语义或报警号表。
> 具体地址范围、参数定义、寄存器占用，以你所使用控制器的官方手册和本包 `paramext.pxt`、`ParamExt_*.xml`、PLC 工程为准。

## 一、先分三个空间

| 空间 | 常见范围 | 型态 | 生命周期 | 主要用途 |
|---|---|---|---|---|
| 区域变数 `#` | `#1~#400` | Double | 本次宏/子程序执行期间 | 引数、临时运算、循环 |
| 轴群记忆 `#` | `#401~#999` | Double | 断电保持（按轴群） | 按轴群保存的数据 |
| 系统变数 `#` | `#1000` 以上 | Long/Double | 随系统状态 | 模态、坐标、刀表、参数、界面信号 |
| 公用变数 `@` | `@1~@165535` | Double/Long | 由区段与参数决定（部分段可断电保持） | 跨宏、跨 PLC、跨画面交换 |
| PLC 寄存器 `R` | `R0~R65535` | 32 位有符号整数 | 由控制器/电池决定 | PLC、宏、画面之间的数据总线 |

关键点：

- `R` 只能存整数，不能存小数；要传小数必须放大（如 ×1000）后传，读侧再除。
- `#` 和 `@` 可以是 Double；但映射到 `R` 的 `@` 段是 Long，写入时会按整数处理。
- `#1~#26` 是 A~Z 引数专用，**不是随便可用的临时变量**；`#27~#400` 才是自由局部区。
- `#33` 不是“第 33 个引数”。引数只到 `#26`；`#33` 只是某个宏自己分配的局部变量。

## 二、`@` 与 `R` 的常见映射

不同控制器版本可能同时保留多套写法，常见三套：

```text
@ = 100000 + R        // R0~R65535，推荐统一写法
@ = 10000  + R        // R0~R4095，旧式别名，和上一行指向同一 R 区
@ = 400    + R        // R1~R255，仅这一段
```

例子：

```text
R8042  -> @108042
R30002 -> @130002
R83    -> @100083   // 也可写 @483
```

注意：

- `@10000~@14095` 与 `@100000~@104095` 都指向 `R0~R4095`；新代码统一用 `@100000+R`，不要两套混用。
- 某个 `@` 段是否断电保持、是否可写，取决于控制器规格与参数设定，不要凭“公用变量”四个字假设。
- 写 R 前先确认该 R 没有被 PLC、通讯、背景运算、客制画面或其它宏占用。

## 三、扩充参数的三种读取路径

很多控制器会把“使用者参数”同时映射到参数号、R 寄存器和宏只读变量。以常见的 `Pr50xx` 段为例：

```text
R  = 8000 + (Pr - 5000)
Pr = 5000 + (R - 8000)
#  = Pr
@  = 100000 + R
```

例：

```text
Pr5001 -> R8001 -> #5001 -> @108001
```

三条路径拿到的并不是同一种东西：

| 路径 | 拿到什么 | 型态/单位 | 适用 |
|---|---|---|---|
| `#50xx` | 该使用者参数的当前值 | Double，单位按参数定义 | 宏内读配置 |
| `PARAM(n)` | 按参数号直接取值 | 单位按参数定义 | 读任意参数，不限 `50xx` |
| `@1080xx` | R 寄存器镜像 | Long，可能是放大后的整数 | 读 PLC/寄存器口径 |

**不要把三者当成完全等价。** 位置/长度类参数常以 μm 或 0.001mm 整数存放；`@108xxx` 参与坐标运算前通常要 `/1000.`，而 `#50xx`/`PARAM()` 是否需要换算要看该参数定义。

## 四、旧参数段不是一条公式

旧 PLC 参数段常见 `Pr34xx`，官方默认至少分两段：

```text
Pr3401~3420:  R = 80  + (Pr - 3400)     // R81~R100
Pr3421~3460:  R = 800 + (Pr - 3420)     // R801~R840
```

例：

```text
Pr3403 -> R83
Pr3421 -> R801
Pr3444 -> R824   // 按官方默认段
```

如果某个包把 `Pr3444` 定义到 `R124`，那是该包的旧映射或客制映射，**不是通用公式**。必须用该包 `paramext.pxt` / `ParamExt_*.xml` / PLC 工程核对后再用。

旧参数段通常没有独立 `#` 直读镜像，但可用 `PARAM(n)` 按参数号读取；单位按该参数定义，不能一律 `/1000.`。

## 五、写 R 的官方入口

常见写法：

```gcode
G10 L1000 P_ R_;
```

- `P`：R 号；
- `R`：写入值；
- G90 下是绝对值，G91 下是增量值；
- 受 `Pr17`（控制精度）与 `Pr3241`（工件程序小数点型态）影响；
- 如果该 R 有物理意义，单位是 LIU（最小输入单位），并受 `G70/G71` 影响。

LIU 口径速记：

| `Pr17` | `G71` 公制 | `G70` 英寸 |
|---:|---|---|
| 1 | 0.01 mm | 0.001 in |
| 2 | 0.001 mm | 0.0001 in |
| 3 | 0.0001 mm | 0.00001 in |

因此 `G10 L1000` 写的是“LIU 计数”，不是固定 mm。详细分支、`@108xxx` 参数镜像与 R 的区别、长度 `/2.54`/速度 `/25.4` 见 `references/macro-core.md` 第四部分。

例子：

```gcode
G71 G90 G10 L1000 P1024 R10.1;   // Pr17=2 时，R1024=10100
G71 G90 G10 L1000 P1024 R0.01;   // 表示 0.01mm，R1024=10
```

和 `@` 写法的区别：

- `@108001 := 1;` 是宏变量赋值，写的是 R 镜像；
- `G10 L1000 P8001 R1;` 是 G 码写 R，受 G90/G91、`Pr17`、`Pr3241` 约束；
- 两者都要考虑 `WAIT()` 与 PLC 扫描时序。

## 六、`#` 的常用区段

| 区段 | 含义 | 备注 |
|---|---|---|
| `#1~#26` | A~Z 引数 | 引数专用，别拿来做临时变量 |
| `#27~#400` | 宏/子程序局部变量 | 子程序与父程序共用，嵌套调用要防覆盖 |
| `#401~#999` | 轴群使用者记忆变数 | `#500~#999` 属于这一段，不是独立公共段 |
| `#1000~#1112` | 模态信息 | 插补、平面、单位、T/M/S/F 等 |
| `#1301~#1488` | 坐标信息 | 当前坐标、G31 触发坐标等 |
| `#1500~#1630` | 操作/状态 | G31 触发旗标等 |
| `#4001~#4100` | 客制参数 | 对应参数段，通常只读 |
| `#5001~#5500` | 使用者参数 | 对应 `Pr5001~5500`，通常只读 |
| `#10000~#15288` | 刀具补偿 | 随刀表型态变化 |
| `#20001~#22018` | 工件坐标系偏移 | 外偏、G54、G54P… |

### 6.1 坐标类怎么选

| 需求 | 用哪个 | 说明 |
|---|---|---|
| 当前机械坐标（命令） | 机械坐标段 | 移动中可能不可读 |
| 当前程序坐标（命令） | 程序坐标段 | 推荐用它取当前位置 |
| 单节终点的程序坐标 | 单节终点段 | 某些补偿/坐标系切换后一行可能读到上一节 |
| G31 触发时的机械坐标 | G31 触发段 | 是触发反馈，不是普通当前位置 |
| G31 触发时的程序坐标 | G31 程序段 | 按轴序读取 |
| 工件坐标（单节终点） | 工件坐标段 | X/Y/Z/A/B/C/U/V/W |

“探测宏里的触发坐标”应理解为：**G31 触发时的坐标反馈**。它之所以能当位置用，是因为前面刚执行了对应轴的 G31；不要把它当成任意时刻的当前坐标。

### 6.2 刀表与索引

单轴刀表常见基址：

```text
刀长几何  #11000 + P
刀长磨耗  #10000 + P
刀径几何  #13000 + P
刀径磨耗  #12000 + P
```

多轴刀表使用另一段基址（常见 `#30000+`）；具体 `P` 的计算方式按控制器刀表规格。

因此现场常见的：

```text
#[11000 + #61]     // 按 #61 里的刀号取刀长几何值
```

是“先算地址，再取值”的索引写法，不是固定变量号。换刀表结构就要换基址。

## 七、取值与间接寻址

### 7.1 直接引数

引数字母与 `#` 编号不是 A~Z 顺序。常见对应：

| 引数 | 变量 | 引数 | 变量 | 引数 | 变量 |
|---|---|---|---|---|---|
| A | `#1` | J | `#5` | S | `#19` |
| B | `#2` | K | `#6` | T | `#20` |
| C | `#3` | L | `#12` | U | `#21` |
| D | `#7` | M | `#13` | V | `#22` |
| E | `#8` | P | `#16` | W | `#23` |
| F | `#9` | Q | `#17` | X | `#24` |
| H | `#11` | R | `#18` | Y | `#25` |
| I | `#4` |  |  | Z | `#26` |

- G/N/O 没有对应 `#`。
- 同一行重复引数通常只有最后一个生效。
- 轴向引数只要一个被宏读取，其他轴向引数可能一起被占用。
- 扩展引数（如 `X1`、`Y1`）不在 `#1~#26` 里，需用控制器提供的具名引数读取方式；常见写法是 `GETARG(X1)`，具体名称以控制器手册为准。
- `#0` 表示“未给”；给 0 时变量值是 0，**不等于 `#0`**。

### 7.2 间接寻址

```gcode
#1 := 123;
@[#1] := 567;        // @123 = 567
@[#1+7] := 890;      // @130 = 890

#10 := 3;
#[11000+#10] := 12.34;   // 等价于 #11003 = 12.34

AR[#1] := 789;       // App 区域变数（如控制器支持）
MAR[#1] := 789;      // App 永久储存变数（如控制器支持）
```

要点：

- `#[表达式]` 是区域变数索引；刀表规格常用 `#[11000+P]`。
- `@[表达式]` 是公用变数索引；先写指针变量，再取值。
- `AR/MAR` 只允许控制器指定的 App 宏使用；越界、负数、小数可能直接报错。
- 间接地址前先做范围检查；指针变量本身要先赋值。
- 不要把“索引”当成“固定映射”：`#[11000+#61]` 的含义是刀表基址 + 刀号。

### 7.3 间接 M 码

```gcode
#201 := PARAM(5317);
M#201;
```

这种写法用于“M 码号由参数决定”的场合；前提是该 M 码已在控制器参数中登记为宏程序。不要假设任意 `M#n` 都能执行。

## 八、变量规划方法

### 8.1 先画数据流

对每个变量写清楚：

```text
谁写 -> 存在哪个空间 -> 谁读 -> 单位/型态 -> 何时失效
```

至少覆盖：宏、PLC、客制画面、参数、报警、外部设备。

### 8.2 按生命周期选空间

| 需求 | 优先选择 | 不要用 |
|---|---|---|
| 单次调用临时值 | `#27~#400` | `#1~#26` |
| 子程序间共用 | `#27~#400`（明确父子关系） | 假设子程序有独立副本 |
| 跨宏、复位内有效 | 系统/电控模态段 | `@1~@400` 当临时区 |
| 断电保持、按轴群 | `#401~#999` | `@1~@400`（默认不保证保持） |
| 跨宏/PLC/画面 | `@` + `R` | 直接读写 PLC 内部寄存器 |
| 配置项 | 参数号 / `#50xx` / `PARAM(n)` | 写 `@108xxx` 改参数 |
| 刀表 | `#10000+` / `#30000+` | 自己另建一套刀补表 |

### 8.3 用“块”而不是“单号”

不要这样：

```text
@920  = 结果
@921  = 标志
@108001 = 开关
```

改成有基址、有偏移的块：

```text
R_BASE = 12000
@HANDSHAKE = 100000 + R_BASE + 0
@RESULT    = 100000 + R_BASE + 1
@FLAG      = 100000 + R_BASE + 2
```

并在交付文档里写一张台账：

| 名称 | 空间 | 地址 | 型态 | 单位 | 写入方 | 读取方 | 生命周期 | 备注 |
|---|---|---|---|---|---|---|---|---|
| `HANDSHAKE` | `@`/R | `R12000` | Long | - | 宏 | PLC | 断电前 | 1=请求 |
| `RESULT` | `@`/R | `R12001` | Long | 0.001mm | PLC | 宏 | 断电前 | 读后 `/1000.` |
| `LOC_TMP` | `#` | `#100` | Double | mm | 宏 | 宏 | 本次调用 | 不要用 `#1~#26` |
| `CFG_MODE` | `#` | `#50xx` | Double | - | 参数 | 宏 | 参数生效 | 只读 |
| `TOOL_LEN` | `#` | `#[11000+#61]` | Double | mm | 宏 | 宏 | 刀表 | 按刀号索引 |

### 8.4 分配前必须检查的占用

- 系统/PLC 标准 R：查本包 PLC 工程的 R 使用表，不要只看“可写范围”。
- 参数镜像段：`R81~R100`、`R801~R840`、`R8001~R8500` 等通常不是空闲寄存器。
- 刀库/刀表：当前刀、目标刀、总刀数、刀表补偿段。
- 通讯/背景运算：NetPLC、Modbus、BGND 等占用的 R。
- 画面：`MST.xml`/`Backgnd.xml` 绑定的 R 与 `@`。
- 其它宏：同目录宏、孪生宏、子程序是否已用同一地址。

## 九、常见错误

1. **把 `#101`、`#301`、`#310`、`#33` 当固定语义**：它们只是局部变量号，换包/换宏就可能代表别的值。
2. **把 `#1~#26` 当临时变量**：会覆盖引数；自由区从 `#27` 开始。
3. **把 `Pr34xx` 套 `Pr50xx` 公式**：`34xx` 至少有两段，且不同包可能重定义。
4. **把 `@108xxx` 和 `#50xx` 当同一个值**：型态/单位/同步机制不同。
5. **直接写参数镜像寄存器改参数**：参数页面可能不会同步，出现参数与寄存器不一致。
6. **往 R 写小数**：R 是 32 位整数；先放大再写。
7. **写 R 后立刻读**：宏可能预读旧值；写后 `WAIT()`。
8. **间接地址不初始化/不查边界**：读到 0、其它变量或直接报错。
9. **认为 `@1~@400` 一定断电保持**：保持性由控制器参数决定，不要假设。
10. **认为 `#500~#999` 是独立公共变量段**：它属于轴群使用者记忆变数一段。
11. **把 G31 触发坐标当任意时刻当前位置**：触发坐标只在刚执行对应 G31 后有意义。
12. **相信“当前刀号固定是某个 `#` 变量”**：不同包/版本口径不同，当前 T 码与当前刀号要分别查本包寄存器与 PLC。

## 十、速查

```text
@ = 100000 + R                 // 全 R 段，推荐
@ = 10000  + R                 // R0~R4095 旧别名
@ = 400    + R                 // R1~R255

Pr50xx:      R = 8000 + (Pr - 5000)   # = Pr
Pr3401~3420: R = 80   + (Pr - 3400)
Pr3421~3460: R = 800  + (Pr - 3420)

读参数:      #50xx / PARAM(n)
读 R 镜像:   @(100000+R)
写 R:        G10 L1000 P<R> R<值>
写刀长:      G10 L10 P<刀号> R<值>
写磨耗:      G10 L11 P<刀号> R<值>
间接区域:    #[表达式]
间接公用:    @[表达式]
```

# 第四部分 单位、精度与公英制

> 通用方法，不含任何厂商内部页面、客户数据或项目参数语义。
> 原则：**先判断“值从哪来、当前是什么单位、要写到哪”，再套公式。** 不要看到寄存器就一律 `/1000.`，也不要看到英寸就一律 `/25.4`。

## 一、四个开关

| 开关 | 常见取值 | 含义 | 影响 |
|---|---|---|---|
| `#1010` | `70` / `71` | `G70` 英寸 / `G71` 公制 | 长度、速度、进给 |
| `Pr17` | `1` / `2` / `3` | 控制精度（最小输入单位 LIU） | R 寄存器、刀表、坐标的整数单位 |
| `Pr3241` | `0` / `1` | 工件程序小数点型态 | `G10 L1000` 的 R 解释；参数镜像的换算分支 |
| 坐标反馈 | `#14xx` / `#13xx` | 机械/程序坐标 | 跟随当前 `#1010` / `Pr17` 口径 |

### `Pr17` 的公制/英寸分辨率

| `Pr17` | `G71` 公制 LIU | `G70` 英寸 LIU | 1 mm 对应 LIU | 1 in 对应 LIU |
|---:|---|---|---:|---:|
| 1 | 0.01 mm | 0.001 in | 100 | 1000 |
| 2 | 0.001 mm | 0.0001 in | 1000 | 10000 |
| 3 | 0.0001 mm | 0.00001 in | 10000 | 100000 |

官方 `G10 L1000` 例子可直接验证：

```gcode
// Pr17=2，G71：R0.01 表示 0.01mm，R1024 存入 10
G71 G90 G10 L1000 P1024 R0.01;

// Pr17=2，G70：R0.01 表示 0.01inch，R1024 存入 100
G70 G90 G10 L1000 P1024 R0.01;
```

### `Pr3241` 的小数点型态

| `Pr3241` | 含义 | 对宏的影响 |
|---|---|---|
| 0 | 小数点型态与 `Pr17` 有关 | 参数镜像先按 `Pr17` 做 `/10`、不变、`*10` |
| 1 | 计算器型（明确小数点） | 常见独立分支：英寸 `/10000.`、公制 `/1000.` |

`Pr3241` 不是单位开关，而是数值解释方式；`=0` 与 `=1` 必须分别实测。

## 二、先分清四种“值”

| 口径 | 典型来源 | 原始单位 | 说明 |
|---|---|---|---|
| 参数镜像 | `@108xxx` | μm / 0.001mm | 固定按 0.001mm 存，不随 `G70/G71` 改变 |
| 一般 R 寄存器 | `G10 L1000`、`Rxxxx` | LIU | 随 `Pr17` + `G70/G71` 改变 |
| 宏内当前单位 | `#44`、`#52` 等 | 当前单位或最小单位 | 看代码分支，不能跨宏推断 |
| 角度 | `@130005` 等 | 0.001° | 只 `/1000.`，不牵涉公英制 |

- `@108xxx` 是参数镜像：`/1000.` 得 mm，`/25400.` 得 inch。
- R 是 LIU 计数：同样写 `1`，在 `Pr17=2/G71` 下是 0.001mm，在 `Pr17=2/G70` 下是 0.0001inch。
- `#` 变量单位由代码决定；同一个 `#44` 在不同宏里可能是测量值或系数，不能跨宏套用。

## 三、基础公式

| 换算 | 公式 | 备注 |
|---|---|---|
| mm → inch | `/25.4` | 1 in = 25.4 mm |
| inch → mm | `*25.4` | |
| μm → mm | `/1000.` | |
| 0.001° → ° | `/1000.` | 角度不牵涉公英制 |
| mm/min → inch/min | `/25.4` | 速度/进给 |
| 0.01mm 单位 → 0.001in 单位 | `/2.54` | **长度专用** |

### 为什么长度是 `/2.54`，速度是 `/25.4`

```text
1 个 0.01mm 单位 = 0.0003937 in = 0.3937 个 0.001in 单位 = 1/2.54
1 mm/min        = 0.03937 in/min = 1/25.4
```

坐标/长度/距离用 `/2.54`；速度/进给用 `/25.4`。写反会差 10 倍。

## 四、标准单位块

```gcode
// 1) 参数镜像（示例：按 0.001mm 存）
#161:=@108039;
#162:=@108037;
#163:=@108038;
#164:=@108040;
#165:=@108035;
#166:=@108036;
#167:=@108032;

// 2) Pr3241=0：按 Pr17 归一化
IF (PARAM(3241)=0 AND PARAM(17)=1) THEN
  #161:=#161/10;   // 0.001mm -> 0.01mm
  #162:=#162/10;
  #163:=#163/10;
  #164:=#164/10;
  #167:=#167/10;
ELSEIF (PARAM(3241)=0 AND PARAM(17)=2) THEN
  // 0.001mm 已是当前单位
ELSEIF (PARAM(3241)=0 AND PARAM(17)=3) THEN
  #161:=#161*10;   // 0.001mm -> 0.0001mm
  #162:=#162*10;
  #163:=#163*10;
  #164:=#164*10;
  #167:=#167*10;
END_IF;

// 3) G70：长度 /2.54，速度 /25.4
IF (#1010=70) THEN
  #161:=ROUND(#161/2.54);
  #162:=ROUND(#162/2.54);
  #163:=ROUND(#163/2.54);
  #164:=ROUND(#164/2.54);
  #165:=ROUND(#165/25.4);
  #166:=ROUND(#166/25.4);
  #167:=ROUND(#167/2.54);
END_IF;

// 4) Pr3241=1：独立分支
IF (PARAM(3241)=1 AND #1010=70) THEN
  #161:=#161/10000.;
  #162:=#162/10000.;
  #163:=#163/10000.;
  #164:=#164/10000.;
  #167:=#167/10000.;
ELSEIF (PARAM(3241)=1 AND #1010=71) THEN
  #161:=#161/1000.;
  #162:=#162/1000.;
  #163:=#163/1000.;
  #164:=#164/1000.;
  #167:=#167/1000.;
END_IF;
```

**执行顺序很重要：** 先 `Pr17` 归一化，再 `G70` 长度/速度换算，最后 `Pr3241=1` 分支。若代码把后两段写成两个独立 `IF`，`Pr3241=1 + G70` 会叠加缩放；这不是互斥逻辑，必须单独实测。

变量号按该宏的实际清单增减，不要照抄固定个数。例如带 X/Y 偏移的盘刀/多轴宏会多出 `#168/#169`，它们同样要参与 `Pr17` 归一化、`G70` 的 `/2.54` 和 `Pr3241=1` 的 `/10000.` `/1000.` 分支。各宏读取的参数镜像清单也可能不同：先看文件头的引数说明和实际赋值，再决定哪些变量要进单位块。

## 五、计数系数

有些宏会维护“每单位计数”系数：

```gcode
#37 := PARAM(17);
IF (#1010=71) THEN
  IF (#37=1) THEN
    #45 := 100.;
  ELSEIF (#37=2) THEN
    #45 := 1000.;
  ELSEIF (#37=3) THEN
    #45 := 10000.;
  ELSE
    #45 := 1000.;
  END_IF;
ELSE
  IF (#37=1) THEN
    #45 := 1000.;
  ELSEIF (#37=2) THEN
    #45 := 10000.;
  ELSEIF (#37=3) THEN
    #45 := 100000.;
  ELSE
    #45 := 10000.;
  END_IF;
END_IF;
```

| 模式 | `Pr17=1` | `Pr17=2` | `Pr17=3` | 异常兜底 |
|---|---:|---:|---:|---:|
| `G71` 公制 | 100 | 1000 | 10000 | 1000 |
| `G70` 英寸 | 1000 | 10000 | 100000 | 10000 |

用途：

```gcode
#52 := ROUND(#52 * #45) / #45;   //量化到当前最小单位
#65 := @806 / #45;               //页面值 -> 当前单位
#53 := ABS(#52 - #18 / #45);     //公差计数 -> 当前单位
```

如果宏用 `CASE` 写系数，必须补 `ELSE` 兜底，防止 `Pr17` 异常时除零。

有些宏还会另设一个“存储系数”用于写回（英寸侧常为公制同精度系数的 2.54 倍）。它与上面的计数系数不是同一个东西；局部变量号可能复用，**不要跨宏套用**。

## 六、固定 `/1000.` 的量

参数镜像一般按 0.001mm 存：

```gcode
#65:=@108034/1000.;   //参数镜像 -> mm
#70:=@108033/1000.;   //公差 μm -> mm
```

注意：

- `#65` 固定转成 mm；如果当前 `G70` 且参与比较的变量是英寸，会混单位。必须实测两边的真实口径，必要时把 `#65` 也 `/25.4`。
- `PARAM(1771)/1000` 是整数除法，会截掉小数；需要小数时写 `/1000.`。
- 把 mm 值与 0.001mm 值相加时，先统一放大再除回：

```gcode
#320:=#168*1000;
#321:=(#66+#320)/1000.;
```

## 七、角度与整数除法

| 量 | 写法 | 说明 |
|---|---|---|
| 角度反馈 | `#200 := @130005 / 1000.;` | 寄存器按 0.001° 存，除 `1000.` 得度 |
| 参数角度 | `#85 := PARAM(1771) / 1000.;` | 需要小数时必须是 `/1000.`，不能写 `/1000` |
| 速度/进给 | `#165 := ROUND(#165/25.4);` | 英寸侧按速度比例 `/25.4`，不是 `/2.54` |

角度只做 `0.001° → °`，不牵涉公英制；不要因为 `#1010=70` 就再除一次 `25.4`。

## 八、攻牙/每转进给

攻牙宏常见的 F 换算：

```gcode
IF( #8 <> #0 AND #9 = #0 ) THEN
  IF( #1010 = 70 ) THEN
    #9 := 1.0 / #8;
  ELSE
    #9 := 25.4 / #8;
  END_IF;
END_IF;
```

- `G70` 英寸侧用 `1.0 / 螺距`；
- `G71` 公制侧用 `25.4 / 螺距`；
- `#8` 的具体含义按该宏文件头确认（螺距/每转进给相关），不要只看这一段就套到别的攻牙宏；
- 除数必须先判非零，避免除零报警。

## 九、`G70/G71` 状态保存与恢复

主动切换公英制的宏必须恢复：

```gcode
@102:=#1010;   //保存 G70/G71
G71;           //宏内统一公制
...
G@102;         //恢复
```

同段还应备份/恢复 `G90/G91`、`G94/G95`。能不切就不切；只读 `#1010` 做换算更安全。

## 十、改单位代码的标准流程

1. 读 `#1010`、`PARAM(17)`、`PARAM(3241)`。
2. 判值来源：参数镜像、R LIU、页面输入、坐标反馈、角度。
3. 判目标单位：mm、inch、LIU、0.001°。
4. 选公式：长度 `/2.54`、速度 `/25.4`、μm `/1000.`、角度 `/1000.`。
5. 保类型：需要小数就写 `1000.`/`2.54`，不要整数除法截断。
6. 写后 `WAIT()`，再读 R/参数。
7. 跑矩阵：`G70/G71` × `Pr17=1/2/3` ×（如支持）`Pr3241=0/1`。
8. 写回 `G10 L10/L2/L11` 后，用 `#`/`@`/`PARAM()` 读回验证单位。

## 十一、检查单

- [ ] `Pr17` 是 1/2/3 哪个？公制/英寸分辨率是否按表写对？
- [ ] `Pr3241=0` 与 `=1` 是否都测过？
- [ ] 长度 `/2.54`、速度 `/25.4`，没有写反？
- [ ] `@108xxx` 是 0.001mm 参数镜像，不是当前 LIU？
- [ ] `G10 L1000` / `G10 L10` / `G10 L2` 的 R 值是否按 LIU/当前单位写入？
- [ ] `PARAM(1771)/1000` 是否故意取整？需要小数时是否写成 `/1000.`？
- [ ] 攻牙/每转进给的 F 是否按 `G70: 1.0/螺距`、`G71: 25.4/螺距` 分支配？
- [ ] `G70/G71` 切换后是否恢复？`G90/G91`、`G94/G95` 是否也恢复？
- [ ] 固定 mm 的绝对量与当前单位变量是否同口径？
- [ ] 所有写 R/参数后是否 `WAIT()`？

## 十二、常见错误

1. 英寸长度用 `/25.4`（本类代码应为 `/2.54`）。
2. 速度用 `/2.54`（应为 `/25.4`）。
3. 把 `@108xxx` 当当前 LIU。
4. `Pr17=1` 与 `=3` 的 `/10`、`*10` 方向写反。
5. 只测 `Pr3241=0`，漏 `=1`。
6. `Pr3241=1 + G70` 的叠加分支没实测。
7. `G70/G71` 切换后不恢复。
8. `G10 L1000` 直接写 mm 值，忽略 LIU。
9. `PARAM(1771)/1000` 整数截断。
10. 固定 mm 的绝对量与英寸变量混算。
11. 攻牙 F 在 `G70/G71` 用了同一个常数，或把螺距当进给直接写。
